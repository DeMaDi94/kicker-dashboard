# Translations

There is **one** translation source for both sides: Laravel's JSON files, `lang/{locale}.json`.
The server uses them through `__('…')`; the client gets the active locale's file as the shared
`i18n` prop and uses them through `t('…')`. No i18n library, no second catalogue.

## The shape

- **Keys are the English source text**, the Laravel JSON convention: `t('Save changes')`.
  English is therefore the source language and needs no file of its own for UI keys — a key with
  no entry falls back to itself. `lang/en.json` exists only for keys whose English text differs
  from the key.
- **Every other supported locale** (`config/app.php` → `locales`) has a `lang/{locale}.json` with
  an entry for **every** key the code uses. `tests/Architecture/TranslationsTest.php` scans
  `resources/js`, `app` and `resources/views` for literal `t('…')` / `__('…')` calls and fails on
  any key a locale file is missing. The Stop gate runs it.
- **Placeholders** are Laravel's: `t('Welcome, :name', { name })`. `:Name` capitalises and
  `:NAME` upper-cases the value, as `__()` does.
- **Laravel's own messages** (validation, auth, passwords, pagination) live in
  `lang/{locale}/*.php`, as the framework expects.

## In React

```tsx
import { useTranslation } from '@/hooks/use-translation';

export function SaveBar() {
    const { t } = useTranslation();

    return <Button>{t('Save changes')}</Button>;
}
```

- Pass a **literal** to `t()`. A computed key (`t(label)`) cannot be checked by the scanner; map
  to a literal first (`status === 'draft' ? t('Draft') : t('Sent')`). An enum's labels belong in
  one function that returns literals.
- A key written in one place and rendered in another — a page's static `layout` props, a nav
  item's `title` — is marked where it is written with `i18nKey('…')` (from `@/lib/i18n`), and the
  component that renders it calls `t(title)`. That is the only computed `t()` allowed.
- Format numbers, amounts and dates with the **active locale** (`useTranslation().locale`, or
  `lib/number.ts`), never a hard-coded `'de-DE'`.
- Outside React (a toast raised from a plain function), take `t` as an argument rather than
  importing a global.

## In PHP

`__('…')` for every string a user reads: validation messages, flashes, mail lines, a refusal
rendered back to the screen. Never concatenate translated fragments — one key per sentence, with
placeholders.

## Adding a key

Add the key to every `lang/{locale}.json` in the same change, with a real translation — never the
English copied in as a placeholder, and never a machine translation of wording a requirement
quotes. Where a requirement quotes UI text in a language, that is the translation for that locale,
verbatim. Keep the JSON files sorted by key; it keeps merges clean.
